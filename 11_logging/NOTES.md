# Logging

## Introduction

Logging is the process of recording important events and information generated by an application.

Backend applications can generate many useful events:

```text
Server started
Request received
User logged in
Invalid input
Authentication failed
Database error
````

Logs help developers understand what is happening inside an application.

---

## Why Logging Is Important

Logging is useful for:

* Debugging
* Monitoring
* Finding errors
* Understanding application behavior
* Investigating unexpected problems
* Tracking important events

Example:

```text
Request
  ↓
Application
  ↓
Log
  ↓
Developer
```

---

## Basic Logging

JavaScript provides `console.log()` for basic logging.

Example:

```javascript
console.log("Server started");
```

Other commonly used console methods include:

```javascript
console.log("Information");

console.warn("Warning");

console.error("Error");
```

---

## Log Levels

Applications commonly organize logs into different levels.

Common levels include:

```text
INFO
WARN
ERROR
DEBUG
```

---

## INFO

`INFO` is used for normal application events.

Examples:

```text
Server started
Request received
User logged in
```

Example:

```javascript
console.log("[INFO] Server started");
```

---

## WARN

`WARN` is used for situations that may require attention but are not necessarily application failures.

Example:

```javascript
console.warn(
  "[WARN] Login request missing email or password"
);
```

---

## ERROR

`ERROR` is used when an actual error or failure occurs.

Example:

```javascript
console.error(
  "[ERROR] Database connection failed"
);
```

---

## DEBUG

`DEBUG` logs are mainly useful during development and troubleshooting.

Example:

```text
[DEBUG] User ID: 10
```

Debug logs should be handled carefully in production because they may contain information that should not be exposed or retained unnecessarily.

---

## Request Logging

Express middleware can be used to log incoming requests.

Example:

```javascript
app.use((req, res, next) => {

  console.log(
    req.method,
    req.originalUrl
  );

  next();

});
```

For a request:

```text
GET /api/users
```

The log can be:

```text
GET /api/users
```

---

## Logging Response Status

The response status code can also be logged.

Example:

```javascript
app.use((req, res, next) => {

  res.on("finish", () => {

    console.log(
      req.method,
      req.originalUrl,
      res.statusCode
    );

  });

  next();

});
```

Example output:

```text
GET /api/users 200
GET /api/users/99 404
POST /login 400
```

---

## Logging Response Time

Response time can be useful for understanding application performance.

Example:

```javascript
app.use((req, res, next) => {

  const startTime = Date.now();

  res.on("finish", () => {

    const duration = Date.now() - startTime;

    console.log(
      `${req.method} ${req.originalUrl} ${res.statusCode} - ${duration}ms`
    );

  });

  next();

});
```

Example:

```text
GET /api/users 200 - 5ms
```

Here:

```text
5ms
→ Approximate time taken to complete the response
```

---

## Logging Middleware Flow

The request logging middleware works like this:

```text
Client
  ↓
Request
  ↓
Logging Middleware
  ↓
Route
  ↓
Response
  ↓
Log Status + Response Time
```

---

## Error Logging

Logging can be combined with centralized error handling.

Example:

```javascript
app.use((err, req, res, next) => {

  console.error(
    `[ERROR] ${req.method} ${req.originalUrl} - ${err.message}`
  );

  res.status(500).json({
    success: false,
    message: "Internal Server Error"
  });

});
```

The server logs the error internally while the client receives a safe response.

---

## Logging and Error Handling

Logging and error handling have different purposes.

### Logging

Records what happened.

```text
Database connection failed
```

### Error Handling

Determines how the application responds to the error.

```json
{
  "success": false,
  "message": "Internal Server Error"
}
```

The two can work together:

```text
Error occurs
   ↓
Log error
   ↓
Handle error
   ↓
Send safe response
```

---

## Sensitive Information

Sensitive information should not be unnecessarily logged.

Do not log:

```text
Passwords
JWT secrets
API keys
Access tokens
Refresh tokens
Credit card information
```

Bad example:

```javascript
console.log(password);
```

Better:

```javascript
console.log(`[INFO] Login attempt for ${email}`);
```

Even emails and other personal data should only be logged when there is a legitimate need.

---

## Structured Logging

Simple logs may look like:

```text
GET /api/users 200 - 5ms
```

More advanced applications may use structured logs.

Example:

```json
{
  "level": "info",
  "method": "GET",
  "url": "/api/users",
  "statusCode": 200,
  "responseTime": "5ms"
}
```

Structured logs are easier for logging systems to search, filter, and analyze.

---

## Logging Libraries

For learning, `console.log()`, `console.warn()`, and `console.error()` are enough.

Production applications often use dedicated logging libraries.

Examples include:

```text
Winston
Pino
```

These libraries provide more advanced features such as:

* Log levels
* Structured logging
* Log formatting
* File transports
* Integration with logging systems

The choice of logging library depends on the application and infrastructure.

---

## Centralized Logging

In larger applications, logs may be sent to a centralized logging system.

Example:

```text
Application Server
       ↓
     Logs
       ↓
Central Logging System
       ↓
Search / Monitoring / Alerts
```

This becomes especially useful when an application runs on multiple servers.

---

## Complete Example

```javascript
const express = require("express");

const app = express();

const PORT = 3000;

app.use(express.json());


// Request Logging Middleware
app.use((req, res, next) => {

  const startTime = Date.now();

  res.on("finish", () => {

    const duration = Date.now() - startTime;

    console.log(
      `[INFO] ${req.method} ${req.originalUrl} ${res.statusCode} - ${duration}ms`
    );

  });

  next();

});


const users = [
  {
    id: 1,
    name: "Ahmed"
  },
  {
    id: 2,
    name: "Ali"
  },
  {
    id: 3,
    name: "Usman"
  }
];


// GET /api/users
app.get("/api/users", (req, res) => {

  res.json({
    success: true,
    users
  });

});


// GET /api/users/:id
app.get("/api/users/:id", (req, res, next) => {

  const id = Number(req.params.id);

  const user = users.find(user => user.id === id);

  if (!user) {

    const error = new Error("User not found");

    error.statusCode = 404;

    return next(error);

  }

  res.json({
    success: true,
    user
  });

});


// POST /login
app.post("/login", (req, res) => {

  const { email, password } = req.body;

  if (!email || !password) {

    console.warn(
      "[WARN] Login request missing email or password"
    );

    return res.status(400).json({
      success: false,
      message: "Email and password are required"
    });

  }

  console.log(
    `[INFO] Login attempt for ${email}`
  );

  res.json({
    success: true,
    message: "Login request received"
  });

});


// Error Testing Route
app.get("/api/error", (req, res, next) => {

  const error = new Error("Something went wrong");

  next(error);

});


// 404 Handler
app.use((req, res, next) => {

  const error = new Error("Route not found");

  error.statusCode = 404;

  next(error);

});


// Centralized Error Handler
app.use((err, req, res, next) => {

  console.error(
    `[ERROR] ${req.method} ${req.originalUrl} - ${err.message}`
  );

  const statusCode = err.statusCode || 500;

  res.status(statusCode).json({
    success: false,
    message: err.message || "Internal Server Error"
  });

});


app.listen(PORT, () => {

  console.log(
    `[INFO] Server started on http://localhost:${PORT}`
  );

});
```

## Common Mistakes

* Logging passwords.
* Logging JWT secrets.
* Logging access or refresh tokens.
* Logging sensitive user information unnecessarily.
* Using only logs without proper error handling.
* Not logging important errors.
* Adding excessive debug logs in production.
* Using inconsistent log formats.
* Assuming `console.log()` is enough for every production application.
